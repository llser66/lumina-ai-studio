# 简历与面试材料

**Lumina 映造 — 基于 LangGraph 的全栈 AI 视觉创作应用**

技术栈：React、TypeScript、Vite、FastAPI、Python LangGraph、OpenAI SDK、SQLite、SSE、Docker、Pytest、Playwright。

新增技术：pi-ai、供应商 OAuth、Fernet 加密、Node 私有 IPC。

## 项目描述

围绕商业素材与个人视觉创作场景，构建包含登录、文生图、参考图编辑、个人作品库、收藏、原图下载与任务追踪的全栈应用；通过 Python LangGraph 编排校验、描述优化、内容检查、生图与归档，使用持久化检查点支持中断恢复。

- 设计事务队列和请求幂等机制，将任务写入与账号 / 全站额度预留放在同一事务；持久化未确认的客户端编号，处理网络中断后的重复提交。
- 将远端计费调用与原图落盘分为明确步骤，关闭 SDK 隐式重试；结果不明时保留额度并进入人工核对，原图已保存时恢复归档。
- 实现 Cookie 认证、CSRF、归属校验、图片验证、SSE 与轮询补偿；通过 API、SDK 协议、故障恢复和浏览器业务测试验证关键行为。
- 集成 pi-ai 的模型目录与供应商授权，构建网页订阅 / API Key / OpenAI 兼容自定义接口管理，支持 OpenAI Codex、DeepSeek 和千问；凭证按用户账户绑定加密保存，默认模型固定到任务，并处理授权取消、失败阶段、令牌刷新与连接撤销。

测试数量与覆盖率引用 VALIDATION.md 的实测值。独立完成、团队规模和负责范围须按实际参与情况修改；理解并继续维护后再作为个人项目经历。

## 面试要点

**为什么用 LangGraph？** 显式图、条件节点与检查点适合长耗时工作流。账号、额度和 CRUD 仍放普通后端。

**为什么不在 HTTP 请求里等待生成？** 浏览器生命周期不应控制后台任务。接口先返回编号，队列继续工作。

**如何控制重复费用？** 业务幂等、客户端未确认编号、禁止 SDK 自动重试、调用标记、原图原子保存和未知结果人工核对；承认无法保证远端全局 exactly-once。

**为什么 SQLite？** 当前单实例目标，事务保护队列和额度，减少基础设施。扩容需 PostgreSQL、队列和对象存储，当前没有伪装实现。

**检查点是什么？** ID、有效描述与文件路径；原图独立存储，业务库负责归属与元数据。

**还有什么待做？** 真实模型验收、公网部署、账号恢复、存储生命周期、遥测与实测性能。覆盖率不是完整安全证明。
